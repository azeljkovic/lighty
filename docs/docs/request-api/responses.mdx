# Responses

Every request helper returns `Promise<RequestResult<TResponse>>`.

```ts
interface RequestResult<TResponse = unknown> {
  status: number;
  ok: boolean;
  headers: Record<string, string>;
  data: TResponse;
  response: Response;
}
```

## Result fields

| Field      | Description                                                                |
| ---------- | -------------------------------------------------------------------------- |
| `status`   | Numeric HTTP status from the response.                                     |
| `ok`       | Same meaning as `Response.ok`; true for status codes in the 200-299 range. |
| `headers`  | Plain object created from `response.headers.entries()`.                    |
| `data`     | Parsed response body. `TResponse` controls its compile-time type only.     |
| `response` | The original `Response` object returned by `fetch`.                        |

## Automatic parsing

When `responseType` is omitted, `lighty` uses the response headers and body content:

- `application/json` responses are parsed with `JSON.parse`.
- `application/octet-stream` responses are read as `ArrayBuffer`.
- Empty responses return `undefined`.
- Other responses are read as text.

```ts
const result = await client.getRequest<{ id: string }>("/users/1");

result.data.id;
```

The response generic is a compile-time cast, not runtime validation. For example,
the code above lets TypeScript treat `data.id` as a string even if the server
returns a number. Use `responseParser` to validate or transform the parsed value.

## Runtime validation and transformation

`responseParser` runs after lighty's normal response parsing. It accepts either a
function or a schema-like object with a `parse(value)` method, so schemas from
libraries such as Zod and Valibot can be passed directly. Its return value becomes
`result.data`; a thrown error rejects the request.

```ts
const User = {
  parse(value: unknown) {
    if (
      typeof value !== "object" ||
      value === null ||
      !("id" in value) ||
      typeof value.id !== "string"
    ) {
      throw new TypeError("Expected a user with a string id");
    }

    return { id: value.id };
  },
};

const result = await client.getRequest("/users/1", {
  responseParser: User,
});

result.data.id;
```

Parser functions additionally receive the raw `Response`, which is useful for
response-aware transformations:

```ts
const result = await client.getRequest("/users/1", {
  responseParser: (body, response) => ({
    body,
    requestId: response.headers.get("x-request-id"),
  }),
});
```

Set `responseParser` in `createClient` to use the same parser for every request;
a request-level parser overrides the client default.

## Forced responseType

Use `responseType` to force a parser.

```ts
const robots = await client.getRequest<string>("/robots.txt", {
  responseType: "text",
});

const image = await client.getRequest<ArrayBuffer>("/image.png", {
  responseType: "arrayBuffer",
});

const stream = await client.getRequest<ReadableStream<Uint8Array> | null>(
  "/events",
  {
    responseType: "stream",
  },
);
```

## Response type reference

```ts
type RequestResponseType =
  | "json"
  | "text"
  | "arrayBuffer"
  | "blob"
  | "stream"
  | "none";
```

| Type          | Runtime result                                                                       |
| ------------- | ------------------------------------------------------------------------------------ |
| `json`        | Reads text and parses it as JSON. Throws `InvalidJsonResponseError` on invalid JSON. |
| `text`        | Reads with `response.text()`.                                                        |
| `arrayBuffer` | Reads with `response.arrayBuffer()`.                                                 |
| `blob`        | Reads with `response.blob()`.                                                        |
| `stream`      | Returns `response.body`.                                                             |
| `none`        | Does not read the body and returns `undefined`.                                      |

## Empty responses

When `responseType` is omitted and the response body is empty, `data` is `undefined`. This is common for `204 No Content`, `HEAD`, and some redirect or error responses.

```ts
const result = await client.deleteRequest<undefined>("/users/1");

if (result.data === undefined) {
  // No response body was returned.
}
```

## Raw Response access

Use `response` when you need fetch-specific metadata that is not copied into the normalized fields:

```ts
const result = await client.getRequest("/profile");

console.log(result.response.redirected);
console.log(result.response.type);
console.log(result.response.url);
```
