# Type reference

This page documents the public types used by request helpers and clients.

## RequestParamValue

```ts
type RequestParamValue =
  | string
  | number
  | boolean
  | null
  | undefined
  | Array<string | number | boolean>;
```

Represents a single query parameter value accepted by `params`.

`null` and `undefined` values are ignored. Arrays are serialized as repeated query parameters.

## RequestParams

```ts
type RequestParams = Record<string, RequestParamValue>;
```

Map of query parameter names to serializable values.

```ts
const params: RequestParams = {
  search: "ada",
  page: 1,
  active: true,
  tags: ["users", "tests"],
  skipped: undefined,
};
```

## RequestResponseType

```ts
type RequestResponseType =
  | "json"
  | "text"
  | "arrayBuffer"
  | "blob"
  | "stream"
  | "none";
```

Controls how `lighty` reads the response body.

| Value         | Parser                                        |
| ------------- | --------------------------------------------- |
| `json`        | `response.text()` followed by `JSON.parse`.   |
| `text`        | `response.text()`.                            |
| `arrayBuffer` | `response.arrayBuffer()`.                     |
| `blob`        | `response.blob()`.                            |
| `stream`      | Returns `response.body`.                      |
| `none`        | Returns `undefined` without reading the body. |

## RequestRedirectMode

```ts
type RequestRedirectMode = "error" | "follow" | "manual";
```

Passed to the underlying `fetch` call as the `redirect` option.

## RequestResult

```ts
interface RequestResult<TResponse = unknown> {
  status: number;
  ok: boolean;
  headers: Record<string, string>;
  data: TResponse;
  response: Response;
}
```

Returned by every request helper.

```ts
type User = {
  id: string;
  name: string;
};

const result: RequestResult<User> = await client.getRequest<User>("/users/1");

result.status;
result.ok;
result.headers["content-type"];
result.data.name;
result.response.url;
```

`TResponse` is a compile-time type assertion only. It does not validate the
response body at runtime; use `ResponseParserHook` when validation is required.

## ResponseParserHook

```ts
type ResponseParser<TResponse> = (
  body: unknown,
  response: Response,
) => TResponse | Promise<TResponse>;

interface ResponseSchema<TResponse> {
  parse(body: unknown): TResponse | Promise<TResponse>;
}

type ResponseParserHook<TResponse> =
  | ResponseParser<TResponse>
  | ResponseSchema<TResponse>;
```

An optional `responseParser` applies this hook after the built-in parser. A
schema-like object is supported so `responseParser: UserSchema` works with schema
libraries that expose `parse`.

## RequestConfig

```ts
interface RequestConfig<TBody = unknown, TResponse = unknown> {
  method: HttpMethod;
  url: string;
  headers?: HeadersInit;
  params?: RequestParams;
  body?: TBody;
  signal?: AbortSignal;
  timeoutMs?: number;
  throwOnHttpError?: boolean;
  responseType?: RequestResponseType;
  responseParser?: ResponseParserHook<TResponse>;
  redirect?: RequestRedirectMode;
  logger?: RequestLoggerConfig;
}
```

The complete request config accepted by `customRequest`.

| Property           | Required | Description                                                                                                                                                      |
| ------------------ | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `method`           | Yes      | HTTP method. `HttpMethod` restricts it to the methods supported by lighty.                                                                                       |
| `url`              | Yes      | Absolute request URL for direct requests. With a client, relative URLs can be resolved through `baseUrl`.                                                        |
| `headers`          | No       | Any `HeadersInit` accepted by `fetch`: plain object, tuple array, or `Headers`.                                                                                  |
| `params`           | No       | Query parameters appended to `url`.                                                                                                                              |
| `body`             | No       | JSON-serialized unless it is a native `fetch` body (`string`, `FormData`, `Blob`, binary data, `URLSearchParams`, or `ReadableStream`), which is passed through. |
| `signal`           | No       | Abort signal passed to `fetch`.                                                                                                                                  |
| `timeoutMs`        | No       | Timeout in milliseconds.                                                                                                                                         |
| `throwOnHttpError` | No       | Defaults to returning non-OK responses. Set `true` to throw.                                                                                                     |
| `responseType`     | No       | Explicit response parser.                                                                                                                                        |
| `responseParser`   | No       | Runtime response validation or transformation hook.                                                                                                              |
| `redirect`         | No       | Fetch redirect behavior.                                                                                                                                         |
| `logger`           | No       | Logger level, disabled flag, or custom logger.                                                                                                                   |

## MethodConfig

```ts
interface MethodConfig<TBody = unknown, TResponse = unknown> {
  headers?: HeadersInit;
  params?: RequestParams;
  body?: TBody;
  signal?: AbortSignal;
  timeoutMs?: number;
  throwOnHttpError?: boolean;
  responseType?: RequestResponseType;
  responseParser?: ResponseParserHook<TResponse>;
  redirect?: RequestRedirectMode;
  logger?: RequestLoggerConfig;
}
```

Used by method-specific helpers where the helper supplies the method and receives URL as a positional argument.

```ts
await postRequest<{ id: string }, { name: string }>(
  "https://api.example.test/users",
  {
    body: {
      name: "Ada",
    },
  },
);
```

## BodylessMethodConfig

```ts
type BodylessMethodConfig<TResponse = unknown> = Omit<
  MethodConfig<never, TResponse>,
  "body"
>;
```

Used by bodyless method helpers.

```ts
await getRequest("https://api.example.test/users", {
  params: {
    active: true,
  },
});
```

TypeScript rejects `body` on helpers that use `BodylessMethodConfig`.

## ClientConfig

```ts
interface ClientConfig<TResponse = unknown> {
  baseUrl?: string;
  headers?: HeadersInit;
  timeoutMs?: number;
  throwOnHttpError?: boolean;
  responseType?: RequestResponseType;
  responseParser?: ResponseParserHook<TResponse>;
  redirect?: RequestRedirectMode;
  logger?: RequestLoggerConfig;
}
```

Defaults shared by a client returned from `createClient`.

`baseUrl` exists only on `ClientConfig`; individual requests use `url`.

## Client

```ts
interface Client<TDefaultResponse = unknown> {
  customRequest<TResponse = TDefaultResponse, TBody = unknown>(
    config: RequestConfig<TBody, TResponse>,
  ): Promise<RequestResult<TResponse>>;
  getRequest<TResponse = TDefaultResponse>(
    url: string,
    config?: BodylessMethodConfig<TResponse>,
  ): Promise<RequestResult<TResponse>>;
  postRequest<TResponse = TDefaultResponse, TBody = unknown>(
    url: string,
    config?: MethodConfig<TBody, TResponse>,
  ): Promise<RequestResult<TResponse>>;
  putRequest<TResponse = TDefaultResponse, TBody = unknown>(
    url: string,
    config?: MethodConfig<TBody, TResponse>,
  ): Promise<RequestResult<TResponse>>;
  patchRequest<TResponse = TDefaultResponse, TBody = unknown>(
    url: string,
    config?: MethodConfig<TBody, TResponse>,
  ): Promise<RequestResult<TResponse>>;
  deleteRequest<TResponse = TDefaultResponse>(
    url: string,
    config?: BodylessMethodConfig<TResponse>,
  ): Promise<RequestResult<TResponse>>;
  headRequest<TResponse = TDefaultResponse>(
    url: string,
    config?: BodylessMethodConfig<TResponse>,
  ): Promise<RequestResult<TResponse>>;
  optionsRequest<TResponse = TDefaultResponse>(
    url: string,
    config?: BodylessMethodConfig<TResponse>,
  ): Promise<RequestResult<TResponse>>;
}
```

## HttpMethod and compatibility types

```ts
type HttpMethod =
  | "GET"
  | "POST"
  | "PUT"
  | "PATCH"
  | "DELETE"
  | "OPTIONS"
  | "HEAD";

type Body = unknown;
type BodyParseError = string | undefined;
```

`HttpMethod` restricts `customRequest` to the request methods supported by
lighty. `Body` and `BodyParseError` are exported compatibility utility types.

## Logging types

```ts
type RequestLoggerLevel = "off" | "basic" | "verbose";
type RequestLoggerConfig = RequestLoggerLevel | false | RequestLogger;

interface RequestLogger {
  level?: RequestLoggerLevel;
  requestStart?: (entry: RequestStartLogEntry) => void | Promise<void>;
  response?: (entry: ResponseLogEntry) => void | Promise<void>;
  requestEnd?: (entry: RequestEndLogEntry) => void | Promise<void>;
}
```

```ts
interface RequestStartLogEntry<TBody = unknown> {
  method: HttpMethod;
  url: string;
  headers: Record<string, string>;
  body?: TBody;
}

interface ResponseLogEntry<TBody = unknown> {
  method: HttpMethod;
  url: string;
  status: number;
  statusText: string;
  ok: boolean;
  redirected: boolean;
  type: ResponseType;
  headers: Record<string, string>;
  body: TBody;
}

interface RequestEndLogEntry {
  method: HttpMethod;
  url: string;
  durationMs: number;
  status?: number;
  ok?: boolean;
  error?: {
    name?: string;
    message: string;
  };
}
```

All logger values are redacted before they reach a hook. See [Errors and
logging](./errors-and-logging#redaction) for the redaction rules and logging
levels.

## Error classes and option types

These public classes and types describe the errors that lighty creates:

```ts
interface HttpRequestErrorOptions<TBody = unknown> {
  status: number;
  statusText: string;
  headers: Record<string, string>;
  body: TBody;
  url: string;
}

interface InvalidJsonResponseErrorOptions {
  status: number;
  statusText: string;
  headers: Record<string, string>;
  body: string;
  url: string;
  cause: unknown;
}
```

```ts
class HttpRequestError<TBody = unknown> extends Error {
  constructor(options: HttpRequestErrorOptions<TBody>);
  status: number;
  statusText: string;
  headers: Record<string, string>;
  body: TBody;
  url: string;
}

class InvalidJsonResponseError extends Error {
  constructor(options: InvalidJsonResponseErrorOptions);
  status: number;
  statusText: string;
  headers: Record<string, string>;
  body: string;
  url: string;
}
```

`InvalidJsonResponseError` also has the original parser error as its standard
`Error.cause`. See [Failure behavior](./errors-and-logging#failure-behavior) for
when these errors are thrown.

## Platform types

| Type | Role |
| --- | --- |
| `HeadersInit` | Accepts the same header inputs as native `fetch`: an object, tuple array, or `Headers`. |
| `AbortSignal` | Enables caller-driven cancellation and timeout composition. |
| `Response` | Exposes the raw Fetch response on `RequestResult.response`. |
| `ResponseType` | Describes the native Fetch response type in `ResponseLogEntry`. |
