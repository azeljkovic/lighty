# Params and body

`RequestParams` and `RequestParamValue` describe the query parameter surface accepted by every request config.

```ts
type RequestParamValue =
  | string
  | number
  | boolean
  | null
  | undefined
  | Array<string | number | boolean>;

type RequestParams = Record<string, RequestParamValue>;
```

## Query parameters

`params` are appended to the request URL:

```ts
await client.getRequest("/search", {
  params: {
    q: "integration testing",
    page: 2,
    active: true,
    tags: ["http", "node"],
    omitted: undefined,
    alsoOmitted: null,
  },
});
```

Serialization behavior:

| Value | Behavior |
| --- | --- |
| `string` | Converted with `String(value)` and set once. |
| `number` | Converted with `String(value)` and set once. |
| `boolean` | Converted to `"true"` or `"false"` and set once. |
| `Array<string \| number \| boolean>` | Appended as repeated query parameters. |
| `null` | Skipped. |
| `undefined` | Skipped. |

For the example above, the resulting URL contains:

```text
?q=integration+testing&page=2&active=true&tags=http&tags=node
```

## Existing URL search params

You can pass a URL that already has query parameters. Scalar `params` use `URLSearchParams.set`, so they replace an existing value for the same key. Array values use `append`, so they add repeated values.

```ts
await getRequest("https://api.example.test/users?page=1", {
  params: {
    page: 2,
    role: ["admin", "editor"],
  },
});
```

## JSON request bodies

When `body` is provided, `lighty` sends `JSON.stringify(body)` to `fetch`.

```ts
await client.postRequest("/users", {
  body: {
    name: "Grace Hopper",
    active: true,
  },
});
```

`Content-Type: application/json` is added automatically for JSON-serialized bodies.

## Body-capable helpers

These helpers accept `MethodConfig<TBody>`:

- `customRequest`
- `postRequest`
- `putRequest`
- `patchRequest`

These helpers accept `BodylessMethodConfig`, which omits `body`:

- `getRequest`
- `deleteRequest`
- `headRequest`
- `optionsRequest`

## Non-JSON bodies

Strings, `FormData`, `Blob`, `ArrayBuffer`, typed arrays, `URLSearchParams`, and `ReadableStream` values are passed directly to `fetch`. This supports raw text, multipart form uploads, binary payloads, and streaming uploads. All other non-null bodies are JSON-stringified.

`Content-Type: application/json` is added only for JSON-serialized bodies. For native bodies, `fetch` can infer the appropriate value (including a multipart boundary for `FormData`); set `headers` yourself when the endpoint requires a specific content type.

```ts
await client.postRequest("/notes", {
  body: "plain text",
  headers: { "Content-Type": "text/plain" },
});

const form = new FormData();
form.append("avatar", new Blob([imageBytes], { type: "image/png" }), "avatar.png");
await client.postRequest("/avatars", { body: form });

await client.putRequest("/archive", {
  body: new Uint8Array([0x50, 0x4b, 0x03, 0x04]),
  headers: { "Content-Type": "application/zip" },
});
```

For a `ReadableStream` body, lighty sets `duplex: "half"`, as required by Node's `fetch` implementation:

```ts
await client.postRequest("/events", {
  body: new ReadableStream({
    start(controller) {
      controller.enqueue(new TextEncoder().encode("event: connected\n\n"));
      controller.close();
    },
  }),
});
```
