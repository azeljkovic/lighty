# Header assertions

Header assertions accept a `RequestResult` or native `Response`. Header names use
the Fetch `Headers` API, which treats names case-insensitively.

```ts
const result = await client.getRequest("/users/ada");

lightyAssert.headerExists(result, "x-request-id");
lightyAssert.headerIs(result, "x-request-id", "request-123");
lightyAssert.headerIncludes(result, "content-type", "application/json");
```

## Available helpers

| Helper | Behavior |
| --- | --- |
| `headerExists(response, name)` | Checks that a header is present. |
| `headerIs(response, name, value)` | Checks the complete header value. |
| `headerIncludes(response, name, value)` | Checks that the header value contains text. |
| `headerMatches(response, name, pattern)` | Checks a regular expression against the header value. |
| `headerSatisfies(response, name, predicate, message?)` | Checks a custom condition. |
| `headerContentTypeIs(response, value)` | Shorthand for an exact `content-type` check. |

Use `headerIncludes` for media types that include parameters such as a charset:

```ts
lightyAssert.headerIncludes(result, "content-type", "application/json");
```

Use `headerContentTypeIs` only when the full value is known:

```ts
lightyAssert.headerContentTypeIs(
  result,
  "application/json; charset=utf-8",
);
```

## Patterns and custom conditions

`headerMatches` resets a regular expression's state before each check, including
for global or sticky patterns:

```ts
lightyAssert.headerMatches(result, "x-request-id", /^request-\d+$/);
```

For checks that do not fit an exact value or pattern, pass a synchronous
predicate. A returned Promise or thenable fails the assertion. If the predicate
throws, lighty preserves that error as the assertion error's `cause`.

```ts
lightyAssert.headerSatisfies(
  result,
  "cache-control",
  (value) => value.includes("max-age="),
  "Expected cache-control to set a max age",
);
```
